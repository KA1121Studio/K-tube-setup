# Windows 11 を自宅サーバー化して K-tube を24時間公開する完全ガイド

このガイドは、Node.js + Express で作成した Web サイト「K-tube」を、Vercel から自宅の Windows 11 PC に移行し、**電源を入れるだけで自動的にインターネットへ公開される状態**にするためのものです。Cloudflare Tunnel を使うため、ルーターのポート開放は一切不要。知識がなくても、そのまま順番に操作すれば必ず完成するように、すべての手順とコマンドを省略せずに記載します。

---

## ① Windows 11 の初期設定

サーバー用途では、PC が勝手にスリープしたり、更新で再起動したりすると困ります。最初にこれらを完全に停止します。

### 1. 電源設定（スリープ・ディスプレイ・HDD停止を無効化）

1. スタートメニューから「**設定**」→「**システム**」→「**電源とバッテリー**」（または「電源とスリープ」）を開く。
2. **画面** の項目をすべて「**なし**」または「**適用しない**」に。
3. **スリープ** の項目もすべて「**なし**」に。
4. 右側の「**電源の追加設定**」をクリック（ない場合は「コントロール パネル\ハードウェアとサウンド\電源オプション」から開く）。
5. 現在選択されている電源プランの「**プラン設定の変更**」→「**詳細な電源設定の変更**」をクリック。
6. 次の項目をすべて「**なし**」または「**0**」に設定する。
   - ハードディスク → 次の時間の後、ハードディスクの電源を切る：**0 分**（「なし」と同じ）
   - スリープ → スリープさせる：**なし**
   - スリープ → ハイブリッド スリープを許可する：**オフ**
   - スリープ → 休止状態にするまでの時間：**なし**
   - USB 設定 → USB のセレクティブ サスペンドの設定：**無効**
   - ディスプレイ → ディスプレイの電源を切る時間：**なし**
7. 「OK」で閉じ、「変更の保存」を実行。

### 2. 自動再起動（システムエラー時）を無効にする

1. 「**設定**」→「**システム**」→「**詳細情報**」→「**システムの詳細設定**」。
2. 「**詳細設定**」タブ →「起動と回復」の「**設定**」。
3. 「**自動的に再起動する**」のチェックを**外す**。
4. 「OK」で閉じる。

### 3. Windows Update による自動再起動を抑制する

完全に止めることは難しいので、更新の再起動を「通知のみ」にする設定と、時間帯を夜中に指定しておきます。

1. 「**設定**」→「**Windows Update**」→「**詳細オプション**」。
2. 「**更新プログラムの通知**」で、再起動が必要なときに通知するよう設定（アクティブ時間帯の設定で再起動を自動実行しないようにできます）。
3. 「**アクティブ時間**」を「手動」にして、サーバーが稼働してほしい時間帯（例：0:00～23:59）に設定。これにより、Windows がその時間帯に再起動しなくなります（完全には防げませんが効果的）。
4. また、**グループポリシーエディター**が使える Windows 11 Pro 以上なら、`gpedit.msc` を開き「コンピューターの構成」→「管理用テンプレート」→「Windows コンポーネント」→「Windows Update」→「自動更新を構成する」を**無効**に設定します。または「自動更新を通知のみでダウンロードしない」ポリシーを有効にします。Home エディションではレジストリから設定可能ですが、簡単のため上述のアクティブ時間設定で十分です。

### 4. BIOS（UEFI）設定：停電後自動起動

PC のマザーボードが対応していれば、停電復旧時に自動で電源が入るようにできます。

1. PC を再起動し、BIOS（UEFI）画面に入る（メーカーごとに Delete キー、F2 キーなど）。
2. 電源管理（Power Management）または「AC Recovery」「Restore on AC Power Loss」といった項目を探す。
3. 設定値を「**Power On**」「**Always On**」または「**Last State**」（最後の状態を復元）に変更する。
4. 保存して終了する。

これで、ブレーカーが落ちて復旧した際、勝手に PC が起動します。

### 5. その他サーバー向け推奨設定

- **高速スタートアップを無効にする**（完全シャットダウンできず、トラブルの元になるため）  
  「コントロール パネル」→「電源オプション」→「電源ボタンの動作を選択する」→「現在利用可能ではない設定を変更します」→「高速スタートアップを有効にする」のチェックを**外す**。
- **Windows Defender ファイアウォール**は後ほど Cloudflare Tunnel のために調整しますが、当面は既定のまま。
- モニター、キーボード、マウスは不要なら外しても構いません。リモートデスクトップで操作できるようにしておくと便利です（「設定」→「システム」→「リモートデスクトップ」で有効化）。

## ② Node.js 環境構築

### 1. Node.js インストール

[Node.js公式サイト](https://nodejs.org/) から「LTS（推奨版）」の Windows インストーラー（.msi）をダウンロードし、実行します。

- インストール中、「**Add to PATH**」にチェックが入っていることを確認。
- 他の設定はデフォルトのまま進めます。
- インストール完了後、PC を再起動するか、コマンドプロンプトを新しく開きます。

動作確認：

```cmd
node -v
npm -v
```

バージョンが表示されれば成功です。

### 2. Git インストール

[Git for Windows](https://git-scm.com/download/win) からインストーラーをダウンロードして実行。

- 基本は「Next」連打でOK。エディタは好みで選んでください。
- **「Adjusting your PATH environment」** 画面では「**Git from the command line and also from 3rd-party software**」を選択（推奨）。
- インストール後、新しいコマンドプロンプトを開いて `git --version` が表示されることを確認。

### 3. GitHub から K-tube をクローン

任意のフォルダにリポジトリをクローンします。ここでは `C:\web\ktube` に配置する例を示します。

```cmd
mkdir C:\web
cd C:\web
git clone https://github.com/あなたのユーザー名/ktube.git
```

GitHub でプライベートリポジトリにしている場合は、Personal Access Token または SSH キーでの認証が必要です。簡易的には、URL にトークンを含める方法：

```
git clone https://YOUR_TOKEN@github.com/ユーザー名/ktube.git
```

トークンは GitHub の Settings → Developer settings → Personal access tokens → Tokens (classic) で生成し、`repo` 権限を付与してください。セキュリティには注意し、後で .env などで管理するわけではないため、トークンを含む URL は履歴に残らないようにします。別途、git の資格情報マネージャーに保存する方法もあります。

### 4. 依存パッケージのインストール

クローンしたフォルダに移動してインストールします。

```cmd
cd C:\web\ktube
npm install
```

`package.json` に定義された全パッケージがインストールされます。エラーが出た場合は、Node.js のバージョンや C++ ビルドツールが必要なネイティブモジュールがないか確認してください。通常 Express だけなら問題ありません。

### 5. .env ファイルの作成

プロジェクトルートに `.env` ファイルを作成し、必要な環境変数を記述します。

例：

```
PORT=3000
SUPABASE_URL=https://xxxxxxxx.supabase.co
SUPABASE_ANON_KEY=eyJ...
JWT_SECRET=あなたの秘密鍵
```

Vercel で設定していた環境変数をそのまま移行してください。**絶対に GitHub にコミットしない**ように、`.gitignore` に `.env` が含まれていることを確認します。

## ③ Express 起動確認（localhost）

### 1. 起動

コマンドプロンプトでプロジェクトフォルダにいる状態で：

```cmd
npm start
```

（または `node api/index.js`。`package.json` の `"start"` が `"node api/index.js"` ならどちらでも可）

正常に起動すると、通常は `Server running on port 3000` のようなメッセージが表示されます。

### 2. ブラウザで確認

同じ PC でブラウザを開き、以下の URL にアクセスします。

```
http://localhost:3000
```

K-tube のトップページが表示されれば成功です。もし開かない場合は、ファイアウォールで Node.js がブロックされていないか確認してください（通常 localhost は許可されています）。

## ④ Cloudflare 設定

ここからドメインとトンネルを設定します。あらかじめ独自ドメインを Cloudflare に登録しておいてください（他社で取得したドメインのネームサーバーを Cloudflare に向ける作業が必要）。

### 1. ドメインを Cloudflare に追加

1. [Cloudflare ダッシュボード](https://dash.cloudflare.com/) にログイン。
2. 「**Websites**」→「**Add a site**」。
3. 使用するドメイン（例：`example.com`）を入力。
4. プランは「Free」を選択。
5. 既存の DNS レコードが読み込まれたら、今はそのまま「Continue」。
6. ネームサーバー変更の指示が表示されるので、ドメイン管理会社のサイトで Cloudflare のネームサーバー（例：`bob.ns.cloudflare.com`）に変更します。反映まで数分～48時間かかることがあります。
7. 「Done, check nameservers」をクリック。

### 2. DNS 設定（あとでトンネル作成時に自動設定される場合もあります）

Tunnel を使う場合、通常は DNS レコードを手動で設定する必要はありません。`cloudflared` が Tunnel 作成時に自動で CNAME レコードを追加してくれます。ここでは特に設定せず進めます。

### 3. SSL/TLS 設定

1. ドメインの管理画面 →「**SSL/TLS**」→「**Overview**」。
2. 暗号化モードを「**Full**」または「**Full (strict)**」に設定します。（Tunnel は Cloudflare とサーバー間が暗号化されるため「Full」で動作します。オリジン証明書は不要です。）

### 4. Cloudflare Zero Trust（Tunnel 作成に必要）

`cloudflared` を使うために Zero Trust ダッシュボードへアクセスします。

1. 左メニュー「**Zero Trust**」をクリック。初回はチーム名の設定を求められます（任意の名前でOK）。
2. 無料プラン（最大50ユーザー）で問題ありません。

Tunnel の作成は次の⑤で行いますが、その前にダッシュボード上の準備は完了です。

## ⑤ cloudflared インストールと Tunnel 構築

Windows 用の cloudflared をインストールし、サービスとして自動起動するまで設定します。

### 1. cloudflared のダウンロード

1. [Cloudflare Zero Trust ダッシュボード](https://one.dash.cloudflare.com/) にアクセスし、左メニュー「**Tunnels**」を選択。
2. 「**Create a tunnel**」ボタンから名前を入力（例：`ktube-home`）→「Save tunnel」。
3. 表示される「**Install and run connectors**」の Windows 用インストーラー（msi）のリンクを使うか、直接 [GitHub Releases](https://github.com/cloudflare/cloudflared/releases) から最新の `cloudflared-windows-amd64.msi` をダウンロードしてインストールします。
4. インストーラーを実行し、すべてデフォルトで完了させます。

### 2. 認証

管理者としてコマンドプロンプトを開き、以下を実行。

```cmd
cloudflared tunnel login
```

ブラウザが起動し、Cloudflare の認証画面が出ます。使用するドメインのアカウントでログインし、「**承認**」します。完了後、証明書が `C:\Users\ユーザー名\.cloudflared\cert.pem` に保存されます。

### 3. Tunnel の作成と設定

先ほどダッシュボードで作成したトンネルと、ローカルの設定ファイルを紐付けます。

```cmd
cloudflared tunnel create ktube-home
```

（トンネル名はダッシュボードで入力したものと合わせます）  
このコマンドにより、証明書やトンネル ID が `C:\Users\ユーザー名\.cloudflared\` 下に JSON ファイルとして作成されます。

### 4. 設定ファイルの作成

`C:\Users\ユーザー名\.cloudflared\` に `config.yml` ファイルを作成し、以下の内容を記述します。

```yaml
tunnel: トンネルID（先ほど作成されたJSONファイル名の英数字）
credentials-file: C:\Users\ユーザー名\.cloudflared\トンネルID.json

ingress:
  - hostname: ktube.example.com
    service: http://localhost:3000
  - service: http_status:404
```

- `トンネルID` は、作成された `.json` ファイルの UUID 部分です（例：`abcdef12-3456-7890-abcd-ef1234567890`）。
- `hostname` は公開したいサブドメインを指定します。事前に Cloudflare の DNS にこのレコードがなくても、Tunnel 起動時に自動で作成されます（ただし、ドメインが Cloudflare に登録されている必要があります）。
- ルートドメイン（`example.com`）を使う場合は、ホスト名に `example.com` を書けばOKですが、サブドメイン `ktube.example.com` などが管理しやすいです。

### 5. DNS への接続（ルート設定）

設定ファイルを使ってトンネルを起動し、DNS レコードを自動設定させます。

```cmd
cloudflared tunnel route dns ktube-home ktube.example.com
```

これにより、Cloudflare ダッシュボード上の DNS に `ktube.example.com CNAME トンネルID.cfargotunnel.com` のレコードが追加されます。

### 6. 起動テスト

手動で Tunnel を起動して動作を確認します。

```cmd
cloudflared tunnel run ktube-home
```

ログに `Registered tunnel connection` と表示されたら成功です。別の端末（スマホのモバイル回線など）から `https://ktube.example.com` にアクセスし、K-tube が表示されることを確認します。このとき、ローカルの Express が起動している必要があります（`npm start` を別のコマンドプロンプトで実行しておく）。

確認できたら、Ctrl+C で一度停止します。

### 7. サービスとしてインストール（Windows 起動時自動起動）

cloudflared を Windows サービスに登録することで、PC 起動と同時に自動で Tunnel が立ち上がります。

管理者としてコマンドプロンプトを開き、以下を実行。

```cmd
cloudflared service install
```

これで「Cloudflared Tunnel」サービスが登録されます。サービスは「自動」スタートタイプで、設定ファイルに基づいてトンネルを起動します。  
正しく動くか確認するには、PC を再起動するか、サービスを手動で開始します。

```cmd
net start cloudflared
```

または「サービス」アプリから「Cloudflared」を探して「開始」。起動後、ブラウザでサイトが表示されれば成功です。

**注意**：サービスとして実行する場合、設定ファイルの `credentials-file` のパスに日本語やスペースが含まれないよう、ユーザーフォルダが英字か確認してください。問題があれば設定ファイルを別の場所に置き、`cloudflared tunnel run` するときに `--config` で指定する方法もありますが、サービス化時は既定の場所から読み込まれます。

## ⑥ PM2 導入（プロセス管理）

Node.js アプリが何らかの原因で落ちても自動復旧させ、さらに Windows 起動時に自動で立ち上がるようにします。PM2 は Windows にも対応しており、`pm2-windows-startup` でサービス化できます。

### 1. PM2 のグローバルインストール

```cmd
npm install -g pm2
```

### 2. K-tube を PM2 に登録

プロジェクトフォルダで以下を実行。アプリケーション名は任意です（例：`ktube`）。

```cmd
cd C:\web\ktube
pm2 start npm --name "ktube" -- run start
```

または `node` を直接指定する場合：

```cmd
pm2 start api/index.js --name ktube
```

どちらでも構いませんが、`npm start` と同じ動作をさせるため上記の npm スクリプト指定が無難です。

起動したら以下のコマンドで状態を確認します。

```cmd
pm2 status
```

一覧に `ktube` が `online` と表示されていればOK。ログを見るには：

```cmd
pm2 logs ktube
```

リアルタイムログが流れます。Ctrl+C で止められます。

### 3. PM2 のスタートアップ登録（Windows 起動時自動起動）

PM2 自体を Windows のサービスとして動かし、保存されたプロセスリストを自動復元する設定です。専用のパッケージをインストールし、スタートアップを設定します。

```cmd
pm2 startup
```

コマンドを実行すると、自動的にシステムに合わせたコマンドが表示されます。Windows の場合、`pm2-startup` というパッケージが導入され、Windows サービス「PM2」が作成されます。表示された指示に従って、必要ならば表示されたコマンドをコピーして実行します（通常は自動で行われます）。

念のため、`pm2 save` で現在のプロセスリストを保存します。

```cmd
pm2 save
```

これで PC を再起動すれば、自動的に PM2 が起動し、先ほど保存した `ktube` も立ち上がります。

### 4. その他の PM2 操作

- アプリの再起動：`pm2 restart ktube`
- 停止：`pm2 stop ktube`
- 削除：`pm2 delete ktube`
- 全アプリの一括再起動：`pm2 restart all`
- ログのリアルタイム監視：`pm2 logs ktube --lines 50`

### 5. 更新時の注意

後述の自動更新で `npm install` 後に再起動する場合も `pm2 restart ktube` を使います。PM2 が管理しているプロセスが、ファイル変更を検知して自動再起動する `--watch` オプションは、本番では使わないほうが安全です。

## ⑦ GitHub 更新の自動化（Push でサイト更新）

ソースコードを GitHub に push したら、サーバー側で自動的に pull → インストール → 再起動が行われる仕組みを作ります。ここでは **Windows タスクスケジューラ**を使って定期的に更新をチェックする方法を採用します。外部からの Webhook を受ける必要がないので安全です。

### 1. 更新用スクリプトの作成

`C:\web\ktube` に `update.bat` という名前のバッチファイルを作成します。以下の内容を記述してください。

```bat
@echo off
cd /d C:\web\ktube

:: リモートの最新情報を取得
git fetch origin

:: ローカルがリモートより遅れているか判定 (mainブランチの場合)
for /f %%i in ('git rev-list HEAD...origin/main --count') do set BEHIND=%%i

if %BEHIND% gtr 0 (
    echo [%date% %time%] 新しいコミットを検出しました。更新します。
    git pull origin main
    call npm install --production
    pm2 restart ktube
) else (
    echo [%date% %time%] 更新はありません。
)
```

- ブランチ名は適宜 `main` や `master` に読み替えてください。
- `--production` を付けると devDependencies をスキップします。必要な開発依存パッケージが動作に必須でなければ、このままでOK。不安なら外します。
- `pm2 restart ktube` は PM2 が管理しているアプリ名に合わせます。

### 2. スクリプトのテスト

コマンドプロンプトで `C:\web\ktube\update.bat` を実行し、正しく動作するか確認します。最初はまだ変更がないので「更新はありません」と出ます。

### 3. タスクスケジューラに登録（5分ごとに実行）

1. スタートメニューから「**タスク スケジューラ**」を起動。
2. 右側「**タスクの作成**」を選択。
3. 「**全般**」タブ：
   - 名前：`Ktube Auto Update`
   - 「**ユーザーがログオンしているかどうかにかかわらず実行する**」を選択。
   - 「**最上位の特権で実行する**」にチェック。
4. 「**トリガー**」タブ → 「**新規**」：
   - タスクの開始：「**毎日**」
   - 開始時間：適当な時刻（例：0:00）
   - 「**繰り返し間隔**」：`5分` を選択し、「**継続時間**」は「**無期限**」。
   - 「**有効**」にチェック。
5. 「**操作**」タブ → 「**新規**」：
   - 操作：「**プログラムの開始**」
   - プログラム/スクリプト：`C:\web\ktube\update.bat`
   - 開始（オプション）：`C:\web\ktube`
6. 「**条件**」タブ：  
   「電源」の「**AC 電源で実行する**」のチェックは外しても構いません（サーバーは常時給電前提なので）。
   「スリープ解除」や「ネットワーク」の項目はそのままでOK。
7. 「**設定**」タブ：
   - 「**タスクをすぐに実行する**」にチェックを入れておきます。
   - 「**スケジュールされた時刻にタスクを開始できなかった場合、すぐにタスクを実行する**」にチェック。
   - その他はデフォルト。
8. 「OK」をクリック。パスワードを求められたら Windows ログインパスワードを入力。

これで5分おきに GitHub をチェックし、更新があれば自動で pull → npm install → PM2 再起動が走ります。

**注意：** GitHub のリポジトリがプライベートの場合、Git が認証情報を覚えている必要があります。`git pull` が成功するように、あらかじめ一度手動で `git pull` を実行して認証情報を保存する（資格情報マネージャーに保存）か、環境変数 `GIT_ASKPASS` を使ってトークンを埋め込むなどの対応が必要です。簡単なのは、`update.bat` 内で `set GIT_ASKPASS=echo` とし、`git pull` にトークン付き URL を使う方法ですが、セキュリティ上注意が必要です。代わりに「Git Credential Manager for Windows」が標準で入っているので、一度手動で `git pull` してサインインしておけば、次回以降は自動で認証が通ります。

## ⑧ セキュリティ設定

### 1. Windows Defender ファイアウォール

ポート開放はしませんが、念のため Express が使用するポート 3000 への外部からのアクセスはブロックされたままにします。Cloudflare Tunnel は外部から PC 内部へ直接接続せず、アウトバウンド接続を確立するため、ファイアウォールのインバウンドルールを追加する必要はありません。既定の設定のままで問題ありません。

### 2. Cloudflare 側の推奨設定

- **SSL/TLS** → エッジ証明書 →「**常に HTTPS を使用**」をオン。
- **セキュリティ** →「**Bot ファイトモード**」をオン（無料プランで有効）。
- **ファイアウォールルール**（WAF）で、不要な国からのアクセスをブロックすることも検討できますが、まずはデフォルトで十分です。
- Zero Trust →「**Access**」→「**Applications**」で、特定のパスに認証を追加することも可能ですが、必須ではありません。

### 3. .env の保護

- プロジェクトフォルダ直下の `.env` は、Web からアクセスされない場所にあります。Express アプリで静的ファイルとして公開しているディレクトリの外に置いてください。
- GitHub には絶対にプッシュしないでください。

### 4. JWT シークレット / Supabase キー

- `.env` に書くキー類は強力なランダム文字列にします。
- Supabase の匿名キーは公開しても大きな問題にはなりませんが、サービスロールキーは `.env` に格納し絶対に漏洩しないよう注意。
- 管理画面がある場合は、Cloudflare Access や簡単なパスワード認証を導入すると安心です。

### 5. 管理画面保護

管理画面の URL に複雑なパスを設定し、環境変数で管理する、もしくは Cloudflare Access で Google 認証などを適用すると強固です。ただし、これは今回の範囲外のため、必要であれば個別に調べてください。

### 6. Windows の自動ログイン設定（任意）

サーバーが停電復旧時に自動起動する場合、Windows のログイン画面で止まらないように「自動サインイン」を設定します。セキュリティリスクはやや高まりますが、物理的に安全な場所に設置するなら問題ありません。

- `netplwiz` を実行し、「ユーザーがこのコンピューターを使うには、ユーザー名とパスワードの入力が必要」のチェックを外す。
- 表示されるダイアログで自動ログインするユーザー名とパスワードを入力。
- 適用して終了。

## ⑨ 運用方法

### 1. 毎日の確認項目

- `https://ktube.example.com` にアクセスし、サイトが正常表示されるか確認。
- PM2 の状態を確認：`pm2 status`（リモートデスクトップまたはローカルで）
- 異常がないか `pm2 logs ktube --lines 20` でエラーログをチェック。

### 2. バックアップ方法

- `.env` と `C:\Users\ユーザー名\.cloudflared\` フォルダ（トンネル証明書類）を定期的に別メディアやクラウドストレージにコピーする。
- Supabase のデータベースは Supabase 側で自動バックアップされているので、そちらに任せます（必要なら手動エクスポート）。
- ソースコードは GitHub にありますが、`.env` 以外のファイルも万が一のためにバックアップしておくと安心です。

### 3. 障害発生時の確認方法

- サイトが落ちている → ローカルで Express が動いているか `pm2 status` で確認。
- Tunnel が切れていないか → サービス「Cloudflared Tunnel」が実行中か確認。または `cloudflared tunnel info ktube-home` で状態表示。
- 再起動方法：`pm2 restart ktube`、もしくは `net stop cloudflared && net start cloudflared`。
- それでもダメなら PC を再起動（自動起動していれば復旧するはず）。

### 4. ログ確認方法

- PM2 ログ：`pm2 logs ktube`
- cloudflared ログ：イベントビューアー（`eventvwr.msc`）の「Windows ログ」→「Application」にソース「cloudflared」で記録される。または `C:\Users\ユーザー名\.cloudflared` 内のログファイルを確認（設定による）。

### 5. アップデート方法

- 通常は GitHub に push すれば自動更新されるため、手動の作業は不要。何らかの理由で自動更新が動作しない場合は、手動で `update.bat` を実行してください。
- Node.js 自体のアップデート：新しい LTS がリリースされたら、公式インストーラーで更新し、再起動後に PM2 が自動復旧するか確認。
- cloudflared のアップデート：`cloudflared update` コマンドで更新可能。サービスを再起動するには `net stop cloudflared && net start cloudflared` を実行。

## ⑩ 電気代・性能の目安

- **消費電力**：一般的なデスクトップ PC でアイドル時 30～60W、ノート PC なら 10～30W。24時間365日稼働で、1kWh=27円とすると、デスクトップで月 600～1300円程度。ノートなら 200～600円程度です。省電力設定（省電力プラン）にしておくと若干下がります。
- **CPU 使用率**：Express 単体のアイドル時は 1%未満。アクセスが集中しても数%～十数%に収まることが多いです。
- **メモリ使用量**：Node.js プロセスで 50～150MB 程度。PM2 や cloudflared を含めても 300MB 以下で十分動作します。8GB あれば余裕。
- **SSD 容量**：OS（Windows 11）で 30～40GB、Node.js やツールで数GB、プロジェクトで数百MB。128GB SSD で十分。
- **通信量**：動画配信サイトでなければ、月間数 GB 以下がほとんど。K-tube が動画共有サイトだとかなり増えますが、個人利用規模なら家庭の光回線で問題になりません。

```
利用者（スマホ・PC）
      ↓
  Cloudflare（DNS, CDN, WAF）
      ↓
 Cloudflare Tunnel（暗号化されたアウトバウンド接続）
      ↓
   Windows 11 PC
      ├─ cloudflared サービス（Tunnel 維持）
      ├─ PM2 サービス（プロセス管理）
      │      └─ Express アプリ（K-tube）:3000

      └─ タスクスケジューラ（GitHub 自動更新）
```

- 利用者は常に Cloudflare のエッジと通信し、オリジンサーバー（自宅 PC）に直接触れることはありません。
- Tunnel は Cloudflare と PC 間を常時接続し、外部からの着信接続を必要としないため、ポート開放不要。
- 電源 ON → Windows 起動 → cloudflared と PM2 が自動開始 → サイト公開完了。

## ⑫ トラブルシューティング

### 1. Tunnel が切れる（サイトにアクセスできない）
- **症状**：`ERR_CONNECTION_REFUSED` や Cloudflare のエラー画面。
- **原因と対処**：
  - `cloudflared` サービスが停止していないか確認：`net start cloudflared` または「サービス」から状態確認。
  - 設定ファイル `config.yml` の `hostname` やトンネル ID が正しいか見直す。
  - `cloudflared tunnel list` でトンネルが存在するか確認。削除されている場合は再作成。
  - ルーターや ISP がアウトバウンド接続をブロックしていないか（通常は問題ない）。
  - ログを確認：`cloudflared tunnel run ktube-home` で直接起動しエラーメッセージを得る。

### 2. Node が起動しない（Express が立ち上がらない）
- **症状**：PM2 がエラーを繰り返す、または `npm start` で落ちる。
- **対処**：
  - `.env` ファイルが正しい場所にあるか、変数名に誤りがないか確認。
  - データベース接続（Supabase）に失敗していないか、APIキー有効性をチェック。
  - 依存パッケージが不足していないか `npm install` を再実行。
  - ポート 3000 が既に使用されていないか `netstat -ano | findstr :3000` で確認。

### 3. HTTPS にならない（ブラウザが「保護されていません」と表示）
- **原因**：Cloudflare の SSL/TLS 設定が「Flexible」のままだと、オリジンへの接続が HTTP のまま。Tunnel は Cloudflare ↔ PC 間で暗号化されているため、必ず「Full」に設定します。
- **対処**：SSL/TLS 概要で「Full」または「Full (strict)」に変更。その後キャッシュクリアして再試行。

### 4. ドメインが繋がらない（DNS エラー）
- **確認**：`nslookup ktube.example.com` で CNAME が `トンネルID.cfargotunnel.com` を指しているか。
- もしレコードが無い場合：`cloudflared tunnel route dns ktube-home ktube.example.com` を再実行。
- ドメインが Cloudflare に正しく登録され、ネームサーバーが変わっているか確認。変更直後は伝播待ち。

### 5. PM2 が起動しない、またはサービスが開始しない
- **症状**：再起動後 `pm2 status` でプロセスがない。
- **対処**：
  - `pm2 save` を実行してから再起動する。
  - `pm2 startup` の設定が有効か確認：`pm2-startup` サービスが「実行中」か。
  - 手動で立ち上げ直す：`pm2 resurrect`。
  - サービスが無効になっている場合は `pm2 startup` を再度実行。

### 6. Windows 起動後にサイトが自動公開されない
- 次の3つが自動起動するようになっているか確認してください。
  1. **cloudflared サービス**：`services.msc` で「Cloudflared Tunnel」が「自動」、状態「実行中」。
  2. **PM2 サービス**：`services.msc` で「PM2」または「pm2-...」サービスが「自動」で実行中。
  3. **Windows 自動サインイン**：PC がログイン画面で停止していないか。上記⑧の自動ログイン設定を確認。
- タスクスケジューラの自動更新タスクは補助的なものなので、直接起動には影響しません。
